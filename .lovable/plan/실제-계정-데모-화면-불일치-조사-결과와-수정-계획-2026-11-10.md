# 실제 계정 / 데모 화면 불일치 — 조사 결과와 수정 계획

## 확인된 사실 (이번 조사에서 직접 확인)
- 연결된 백엔드는 하나뿐이며, 미리보기와 배포된 앱이 같은 백엔드를 씁니다.
- 현재 가입 계정 2개, 모두 이메일 인증 완료, 프로필 2개 연결됨.
- 실제 계정 모드 설정(`VITE_BACKEND_MODE`)은 프로젝트 어디에도 없습니다. 따라서 미리보기와 배포본 모두 **데모 모드**로 동작합니다.

## 원인
- A. Account 화면(로그인 화면)은 모드와 관계없이 항상 실제 로그인 세션과 프로필을 읽습니다 → 실제 이메일·이름 표시.
- B. Profile 화면은 데모 모드일 때 데모 화면(Alex Morgan)을 그리도록 되어 있고, 설정이 없어 항상 데모 모드입니다.
- C. 이전 "계정 0개" 보고는 같은 백엔드를 확인한 것이며, 그 시점 이후에 가입이 이뤄진 것으로 보입니다(가설 — 가입 시각은 개인정보라 출력하지 않음). 다른 백엔드를 본 것은 아닙니다.

## 수정 (최소 범위)
- 이 프로젝트의 환경 설정 파일은 자동 관리되어 새 설정값을 넣을 수 없으므로, 모드 결정 파일 한 곳에서 기본값을 **실제 계정 모드**로 바꿉니다.
- 데모 모드는 유지: 명시적으로 데모를 지정하면(`VITE_BACKEND_MODE=demo`) 기존 데모 동작 그대로. 테스트는 이미 모드를 직접 지정하므로 영향 없음.
- 사용자 데이터·보안 규칙·로그인 설정은 건드리지 않습니다. 배포하지 않습니다.

## 영향 (승인 필요)
- 기본 화면이 실제 계정 모드가 됩니다: 데모 시계 영상·Silent Offer·채팅 데모 대신 실제 게시물/빈 상태, 오퍼·채팅은 "Coming Soon".
- 배포된 앱에 반영하려면 별도로 게시 승인이 필요합니다.

## 검증
- 관련 테스트, 타입 검사, 배포용 빌드 실행.
- 가능하면 실제 계정 세션으로 미리보기 Profile에 실제 이름이 나오는지 브라우저 확인; 못 하면 NOT TESTED로 표기.
